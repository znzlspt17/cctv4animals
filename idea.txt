# DeepFace Live — 실시간 얼굴 인식 웹 애플리케이션

## 개요
웹캠 영상에서 실시간으로 얼굴을 인식·등록·검색하는 시스템.
DeepFace 라이브러리 기반으로 얼굴 임베딩을 추출하고, 원격 PostgreSQL DB에 메타데이터를 저장한다.

## 아키텍처
- FastAPI 백엔드 + Streamlit 프런트엔드 + 원격 PostgreSQL의 3-tier 구조로 역할 분리
- Repository Pattern으로 DB를 추상화하여 SQLAlchemy ORM → PostgreSQL 사용

## 얼굴 인식 엔진
- DeepFace + RetinaFace(detector) + VGG-Face(model) 조합으로 5-point landmark 기반 정밀 임베딩 추출
- cosine distance 기반 중복 판정(threshold 0.40)과 numpy 벡터화 행렬 연산으로 brute-force 검색
- 다중 각도/조명 이미지를 한 세션에 일괄 등록하되 첫 이미지만 중복 체크 수행
- 같은 얼굴이 중복 등록되지 않도록 cosine distance ≤ threshold 시 409 Conflict 반환
- 강제 등록 옵션(ALLOW_FORCE_REGISTER)과 쌍둥이/마스크 등 경계 사례 처리 지원

## DB / 저장소
- persons(메타), face_images(임베딩+경로), recognition_logs(로그), alert_rules(알림), person_name_seq(시퀀스) 5개 테이블 설계
- 처음 등록하는 사람의 이름은 순차적으로 person1, person2… 시퀀스로 자동 증가
- 이미지 원본은 로컬 파일시스템(face_db/)에 저장하고 DB에는 경로 링크만 기록
- 인물별 전화번호, 주소 등 추가 정보를 옵션으로 관리(extra_info JSON 확장)

## 실시간 스트리밍
- streamlit-webrtc의 VideoProcessorBase 콜백에서 N프레임마다 1회 인식 호출(frame skip)로 CPU 부하 제어
- 인식 결과를 실시간으로 영상 위에 오버레이(이름 + 선택적 정보 표시)

## UI (Streamlit 5페이지)
- 실시간 인식: WebRTC 영상 + 얼굴 바운딩박스·이름 오버레이
- 얼굴 등록: 다중 각도 촬영 가이드 + 중복 미리보기 + 추가 정보 입력
- 인물 관리: 등록 인물 CRUD + 알림 규칙 설정
- 로그 조회: 날짜/인물 필터링 + plotly 통계 차트
- 설정: threshold 슬라이더, 오버레이 토글, DB 상태 확인, 로그 레벨 조정

## API 설계
- 인물 CRUD 5개, 인식/등록/다중각도 3개, 로그 조회/통계/정리 3개 — 총 11개 REST 엔드포인트

## 알림
- person별 alert_rules 테이블로 규칙 관리, 인식 시 활성 규칙 매칭하여 st.toast() 팝업 표시

## 환경 설정 (.env)
- DB접속, 모델/검출기, threshold, 프레임스킵, 로그레벨/포맷/파일출력 등 20+개 환경변수를 pydantic-settings로 통합 관리

## 로깅
- Python logging + RotatingFileHandler로 DEBUG~CRITICAL 5단계 레벨별 콘솔+파일 출력
- 외부 라이브러리 노이즈 억제, 인식 로그 DB 보관(TTL) + 동일 인물 중복 로그 억제

## 성능 최적화
- lifespan startup에서 DeepFace 모델 워밍업(콜드스타트 방지) + 임베딩 메모리 캐시 로드
- numpy 기반 cosine distance 브루트포스 벡터 검색

## Python 환경
- Python 3.12.x 기반, venv 가상환경(.venv/)으로 격리
- tensorflow 2.16~2.17 (deepface 암묵적 의존) + numpy <2.0 호환 조합 확정
- Python 3.13은 tensorflow 호환 불확실 → 3.12.x 고정
- 전체 18개 패키지 버전 고정 (requirements.txt)

## 테스트
- pytest + httpx AsyncClient 기반, Repository Mock/Stub으로 양쪽 백엔드 단위테스트 + API 통합테스트

## 인프라
- 원격 PostgreSQL 사용 (로컬 Docker 컨테이너 없음)
- DATABASE_URL 환경변수로 접속 정보 관리
